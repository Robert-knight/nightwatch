# 守夜 NIGHTWATCH

一个家庭安防公司的官网。它卖给你一台摄像机。
你往下滚，会发现它一直在拍的不是你的家。

**建议戴耳机。**

---

## 怎么看

双击 `index.html`。纯静态，无依赖、无构建、无外部请求。

```bash
python -m http.server 8123     # 或直接双击
```

进来是一道正常的产品启动页，点「进入官网」——顺便解锁声音（浏览器不给自动播放）。

## 节奏：正常 → 不对劲 → 害怕 → 被吓到

全文约 **20 屏**，是按比例设计过的：

| 进度 | 内容 | 氛围 |
| --- | --- | --- |
| 0 – 6% | 首页：产品图、卖点、两个 CTA、128,904 个家庭 | **完全正常** |
| 6 – 12% | 五个参数条 + 合作伙伴 | 正常 |
| 12 – 22% | 为什么：白天入室、六个小时、四组数据 | 正常（用恐惧做营销） |
| 22 – 30% | 四张功能卡 + 三步安装 + 用户评价 + 媒体引述 | 正常 |
| 30 – 45% | 实拍：一条走廊，尽头一扇亮着的门 | **不对劲** |
| 45 – 48% | 再看一眼：另一台，同样的走廊 | 不对劲 |
| 48 – 56% | 隐私承诺、定价 | **害怕** |
| 56 – 62% | 常见问题 | 害怕 |
| 62 – 70% | CTA、页脚 | 害怕 |
| 70 – 100% | 全屏监控，它在走近，然后「现在，回头。」 | **被吓到** |

**声音是渐入的，不是一直在的。** 进入官网后是**完全的静音**（主增益 0.0001，A 计权下听不见）。滚到全文 17% 左右，低频嗡鸣才开始从无到有地渗进来；36% 之后心跳才加入；越往下越响、越密。页面同步变暗：一层暗角随进度从 0 爬到 0.66，像房间在收拢。

## 恐怖设计

**五次惊吓，每次都卡在它该在的位置：**

1. **~27%**（实拍屏刚进视野）— 一帧人脸，60ms，40% 不透明 + 一声脆响。只够你怀疑自己。
2. **~37%**（走廊里那个人出现后）— 它从远处**硬切**到镜头前，低频撞击 + 屏幕抖 + 白闪；260ms 后回到远处，画面里又什么都没有了。
3. **~48%**（隐私页落定）— 整页断电 260ms，同时一声敲门从**左侧**传来（StereoPanner）。
4. **~58%**（常见问题）— 你读到「可以随时关掉吗？」时，右边一声敲击 + 一记脆响，什么也没有发生。
5. **~88% 的终章**—「现在，回头。」→ 环境音被整个掐掉 1.5 秒 → 尖啸 + 人影撞上镜头 + 两帧白闪 + 过曝的脸 + 黑场。之后三秒死寂。

**第一次往下滚，前面 30% 是完全干净的。** 所有文案腐化（评价、媒体、功能卡副标）都设成 `t: 1.0`——只有当你滚**回去**才会发现它变了。往下走的路上，你看到的每一屏都是正常的。

## 技术

| 文件 | 作用 |
| --- | --- |
| `index.html` | 入口 + 11 个版块 + 终章舞台 |
| `style.css` | 冷色技术美学、扫描线、暗角、压迫层、崩坏状态 |
| `main.js` | 监控画面渲染、恐怖音效引擎、惊吓导演、滚动编排 |

- **三块监控画面**（实拍 / 再看一眼 / 终章全屏）共用同一条 canvas 渲染管线：走廊透视、门口的光、颗粒、滚动扫描带、故障切片、按透视缩放的人影。
- **人影是几个路径拼的纯黑剪影**，靠亮着的门反衬出来；距离用 `0.16h / (1 - z)` 做透视衰减。
- **所有惊吓由元素自身的位置触发**（`getBoundingClientRect`），不写死像素，任何屏幕高度下都落在同一叙事位置。
- 音频全部 WebAudio 现场合成：失谐锯齿嗡鸣、房间呼吸、随紧张度加速的心跳、噪声 riser、FM 尖啸、撞击、立体声敲门、压缩器限幅、ducking。

## 已修的问题（v2.2）

### 1. 刷新后直接跳进惊吓

浏览器在 `load` **之后**才恢复滚动位置，而 `scrollTo(0,0)` 跑在 `DOMContentLoaded`，被覆盖了。点进去时页面已经站在半路，所有基于元素位置的惊吓立刻全部触发。

三层修法：

1. `history.scrollRestoration = 'manual'`（脚本第一行，早于任何导航状态）；
2. `load` 里再 `scrollTo(0, 0)` 一次；
3. 所有惊吓加一道 `S.armed` 闸门——只有页面**曾经出现在顶部附近**（`p < 0.05`）才武装。

实测（CDP 驱动真实浏览器：滚到 9000 → 刷新 → 再进入）：`scrollAfterReload: 0`，`fired: {}`，脸层不透明度为空。

### 2. 有耳机也听不到氛围音

**根因不是频谱，是一个重复定义。** `A` 对象里有两个 `setTension`：新写的那个设置 `this.level` 并调用 `applyGain()`，但它被后面遗留的旧版本覆盖了——旧版只改 `this.tension` 和滤波器，从不碰主增益。于是主增益永远停在 0.0001（-80 dB）。

jumpscare 之所以响，是因为它走的是另一条路：`duck()` → `punch()` → `applyGain()`，那条路径直接把增益推到 0.8。

这也解释了为什么我上一轮的离线测量"通过"了——我在测试里把 `setTension` 冻结、手动设置 `level`，**恰好绕开了坏掉的那段代码**。教训：测试不能替换掉被测对象。

修掉重复定义后，实时读数（真实浏览器，滚动到不同位置）：

| 位置 | level | 主增益 | 等效 |
| --- | --- | --- | --- |
| 刚进门 | 0 | 0.0001 | 静音 |
| p=0.19 | 0.038 | 0.126 | -18 dB |
| p=0.35 | 0.342 | 0.301 | -10.4 dB |
| p=0.51 | 0.646 | 0.361 | -8.9 dB |
| p=0.68 | 0.975 | 0.688 | -3.2 dB |

同一套 `setTension` 在离线渲染里的分频段实测：

| level | 总电平 | 300–800 Hz | 2–6 kHz |
| --- | --- | --- | --- |
| 0 | **-96.5 dB（峰值 0）** | — | — |
| 0.2 | -28.7 | -30.9 | -35.7 |
| 0.5 | -22.8 | -25.6 | -24.9 |
| 1.0 | -16.1 | -20.7 | -15.1 |

（顺带做的混音改动：次低频压到三分之一；压缩器从混音元件改成安全限幅 -9 dB / 4:1；新增 186–352 Hz 的 body 层；空气层从棕噪声换成白噪声并抬到 2.4 kHz；心跳补 165 Hz 成分。）

## 音量重新定标（v2.3）

上一版把氛围音做"实"了，但整体电平太高：终点处主增益 0.74，耳机里低频持续压着耳朵，而且和惊吓几乎没有落差。重新定标后：

**床（氛围）与惊吓的实测对比**（同一套代码，离线渲染）

| | RMS | 峰值 |
| --- | --- | --- |
| 氛围（紧张度 1.0） | **-24.7 dBFS** | 0.219 |
| 惊吓（duck → punch → 尖啸 + 撞击） | **-13.7 dBFS** | 0.744 |

落差 **+11 dB**，而且惊吓之前有 1.5 秒的完全静音（`duck(1500)`），所以是「安静 → 炸」而不是「更响的吵闹 → 更响」。

**实时读数**（真实浏览器）

| 位置 | 主增益 |
| --- | --- |
| 刚进门 | 0.0001（-80 dB） |
| p=0.19 | 0.057（-24.9 dB） |
| p=0.35 | 0.130（-17.7 dB） |
| p=0.68 | 0.265（-11.5 dB） |
| 终章惊吓瞬间 | **1.0**，之后落到 0.005（房间安静下来） |

具体改动：主增益上限 0.74 → 0.27；次低频层再降（`droneGain` 0.17→0.10、27.5 Hz 正弦 0.09→0.05），这是耳机上"耳朵疼"的主要来源；空气层 0.05+0.5L → 0.02+0.16L（嘶声不再压在最上面）；出口加了一级真正的限幅器（-6 dB / 20:1）防止瞬态过冲；惊吓的 punch 提到 1.0、尖啸增益 0.75→1.0；惊吓之后房间保持安静一分钟，不再立刻涨回来。

## 怎么分享

整个站是纯静态的：三个文件 + 一个预览图，没有构建、没有依赖、没有外部请求。任何静态托管都能直接放上去。

### GitHub Pages

```bash
git init
git add .
git commit -m "守夜 NIGHTWATCH"
git branch -M main
git remote add origin https://github.com/<你的用户名>/nightwatch.git
git push -u origin main
```

然后到仓库 **Settings → Pages**：Source 选 `Deploy from a branch`，Branch 选 `main`、目录 `/ (root)`，保存。一分钟左右上线：

```
https://<你的用户名>.github.io/nightwatch/
```

仓库名如果想短一点，可以让它等于 `<用户名>.github.io`，网址就是 `https://<用户名>.github.io/`。

所有引用都是相对路径（`style.css`、`main.js`、`og.jpg`），放在子目录里也能正常跑，不需要改任何东西。`.nojekyll` 已经放好了，可以跳过 Jekyll 处理。

### 更快的办法

- **Netlify Drop**：把整个文件夹拖到 app.netlify.com/drop，立刻拿到一个网址（要长期保留需登录）。
- **Cloudflare Pages**：连 GitHub 仓库或直接上传，免费、国内访问通常比 GitHub Pages 稳。
- **发文件**：打包成 zip 直接发，对方解压后双击 `index.html` 也能看（但 `file://` 下音频解锁和滚动行为因浏览器而异，建议还是用网址）。

### 分享时提醒一句

- **点「进入官网」之后才有声音**——这是浏览器的自动播放限制，不是坏了。
- 页面里有**突发强音和闪烁画面**，最好让朋友戴耳机、别在深夜外放。
- 桌面浏览器效果最完整；手机上能看，但瞳孔追踪、部分视差会弱化。

### 仓库里放什么

| 文件 | 需要吗 |
| --- | --- |
| `index.html` / `style.css` / `main.js` | 必须 |
| `og.jpg` | 建议：链接分享时的预览图 |
| `README.md` | 建议 |
| `screens/` | 可选，5.3 MB，只是截图 |
| `.nojekyll` | GitHub Pages 用得上 |

嫌仓库大的话，把 `screens/` 删掉或加进 `.gitignore` 即可，不影响网站。
